# ADR-0009: Agent-to-agent (A2A) protocol — not used inside ClinScribe

Status: Proposed · Date: 2026-10-13

## Context

ClinScribe's agents are nodes of one LangGraph graph in one process, and its tools are MCP servers
(guidelines-mcp, druggraph-mcp, fhir-mcp). The A2A protocol is for agents run by *different* parties
to discover each other (agent cards), exchange tasks and stream results across organisational
boundaries. SPEC §5 asks for an ADR on where it would fit.

## Options

1. **No A2A**: graph nodes call each other through state; tools through MCP (current).
2. **A2A between ClinScribe's own agents** (note writer, Ask agent, lab parser as A2A services).
3. **A2A at the edge only**, for a future hand-off to another organisation's agent.

## Decision

Option 1 now, option 3 when there is an external partner. Inside one system A2A would add network
hops, a second auth layer and task lifecycle state that the graph already holds, and it would move the
human-approval stop out of one inspectable graph. The natural first use is a **referral hand-off**:
an approved referral letter (FHIR `ServiceRequest` + `DocumentReference`) sent to another
organisation's intake agent, which publishes an agent card, accepts the task and returns its status.

## Consequences

- No A2A dependency or endpoint today.
- If a referral agent is added: only approved, de-identified-or-consented content leaves; the A2A call
  is audited like a FHIR write (actor, model, prompt version); the partner's agent card and auth are
  reviewed like any subprocessor (GDPR DPA, HIPAA BAA where PHI is involved).
- MCP stays the tool contract; A2A would sit beside it, not replace it.
